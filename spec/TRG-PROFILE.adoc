== About this profile

This profile applies the *TRG v1.0* baseline to the My toolchain.
The codebase is structurally substantial — a 14-crate Rust
workspace with the bulk of the compiler in `crates/my-lang/`
(parser 2867 lines, checker 1792 lines, interpreter 955 lines,
stdlib 1931 lines, ast 833 lines, lexer 540 lines), plus an LLVM
backend (`my-llvm` 1077 lines using inkwell), HIR (`my-hir`
666 lines), MIR (`my-mir` 1596 lines), LSP scaffold (`my-lsp`
515 lines), formatter (`my-fmt` 456 lines), linter (`my-lint`
352 lines), package manager (`my-pkg` 377 lines), CLI driver
(`my-cli` 764 lines), DAP scaffold (`my-dap`), debugger scaffold
(`my-debug`), AI scaffold (`my-ai` 778 lines), test runner
(`my-test`), and a separate parser scaffold (`my-parser`,
non-load-bearing TODO).

The overall grade lands at *D* rather than C because:

* M5 *semantics document* is partial — `grammar.ebnf` (381 lines)
  + `spec/system-specs.md` cover surface syntax but not
  operational/denotational semantics with the rigor required at
  grade C.
* B3 *backend registry* is N/A (single LLVM backend), so it does
  not bind the grade.
* T9 *pipeline orchestrator* runs implicitly through `cargo` +
  `my-cli`; no discrete orchestrator artefact.
* No per-component audit documents at `audits/audit-<component>.md`
  per TRG §3 + §4.
* T3 *REPL* is not separately discoverable in the inventory.

The chain of axes:

* ARG: *D-leaning-E* (per `spec/ARG-PROFILE.adoc` — toy-project
  usable in places, multi-dialect ambition not matched by external
  adoption)
* TRG: *D* (this profile)
* FRG: *X* (per `spec/FRG-PROFILE.adoc` — template ABI scaffolding
  honestly retracted 2026-03-29 without domain-specific replacement)
* CRG: *D* (per `spec/CRG-PROFILE.adoc`; no crates.io publication)
* RSR: Compliant at TRG-D level

Cross-axis rule: ARG ≤ TRG holds (TRG = D ≥ ARG = D-leaning-E).

== Component grades

component is graded independently against the four-tier audit format
of TRG §4 (Must / Should / Could / Aspirational → grades E / D / C / B).
The overall TRG grade is the *worst* of any MUST component.

== Language-specific tightening (this profile only)

TRG §1.1 permits per-language tightening. For My, the following
additional obligations apply at the stated grades:

* *Grade D tightening:* The four-dialect progression (visual blocks
  → solo → duet → ensemble) MUST be reflected in the lexer +
  parser as dialect tags. Currently `dialects/solo/` and
  `dialects/duet/` are committed; `dialects/ensemble/` and
  `dialects/me/` are designed-but-not-yet-implemented.
* *Grade C tightening:* A canonical semantics document (M5) MUST
  cover the dialect-projection rules (each dialect a structural
  subset of the next).
* *Grade B tightening:* `my-lang` MUST be self-hosting in at least
  one dialect (likely `solo`), OR a published rationale MUST
  explain why Rust is the strategic implementation language
  indefinitely.
* *Grade A tightening:* Idris2 ABI declared + Zig FFI declared +
  domain-specific Idris2 proofs of the dialect-projection
  judgement (paired with FRG ≥ C).

These tightenings are *additional* to the baseline — none of the
baseline evidence is waived.

== What is NOT yet met (honest gaps)

Gating gaps for grade *C*:

* *M5 canonical semantics document* — `grammar.ebnf` +
  `system-specs.md` cover surface syntax but not operational +
  denotational semantics. Gates grade C.
* *B5 ABI / FFI surface* — neither Idris2 ABI nor Zig FFI declared,
  in tension with the estate-wide convention from `CLAUDE.md`.
* *Per-component audits* — no `audits/audit-<component>.md` files
  per TRG §3 + §4.
* *T3 REPL* — either ship one or document the absence per TRG §3.

== Path to next grade (*C*)

* Write `spec/semantics.adoc` consolidating operational +
  denotational semantics with the dialect-projection judgements.
  (~3-4 weeks)
* Declare the Idris2 ABI + Zig FFI surfaces (even if minimal
  placeholders that grow with the language). (~2-3 weeks)
* Add per-component audit documents under `audits/`. (~3-4 weeks)
* Decide T3: either ship a REPL or document the absence.

*Realistic timeline estimate:* 2-3 months from current state.

== Path to grade beyond that (*B*)

* Self-host at least the `solo` dialect in My itself, OR publish
  the rationale for Rust as the strategic implementation language.
* Land the `dialects/ensemble/` + `dialects/me/` directory contents
  matching the four-dialect progression.
* External-consumer evidence beyond the playground.

== Demotion risk

* *Lowest:* `tests/integration_test.rs` or `tests/property_tests.rs`
  regress significantly.
* *Medium:* `crates/my-llvm` codegen path breaks for the primary
  x86_64-linux target.
* *Catastrophic:* The 14-crate workspace decomposition is found to
  be load-bearing on a crate that fails to build for upstream
  Rust toolchain reasons (rustc / inkwell API drift) and is not
  promptly fixed.
